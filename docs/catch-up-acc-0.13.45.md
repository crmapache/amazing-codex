# Догоняем оригинал: ACC 0.13.29 - 0.13.45

Перенос 2026-10-17 - 2026-10-18, ветка `catch-up/acc-0.13.44`. Предыдущий шаг - `docs/catch-up-acc-0.13.28.md`.

## Как переносилось

- Точка: форк содержал ACC до 0.13.28 (перенос 0.3.0). Два диапазона оригинала: `5280788..747f96f` (0.13.29 -
  0.13.44, 36 коммитов, 256 файлов, ~19.8 тыс. строк) и `747f96f..6a781c3` (0.13.45, 3 коммита, 72 файла, ~2.7 тыс.
  строк).
- Трёхстороннее слияние `git merge-file` с переименованием под форк (`amazingclaudecode` -> `amazingcodex`,
  `claude/` -> `codex/`, `Claude*` -> `Codex*`, кроме `ClaudeCode`, `ClaudeModels`, `ClaudeProjectConfig`). Первый
  диапазон: 140 файлов слито чисто, 56 с конфликтами разобрано руками, 47 новых, 11 пропущено, один удалён
  (`DayChart.tsx`). Второй: 46 чисто, 3 с конфликтами, 15 новых, 8 пропущено.
- Не сливались, а переносились руками: `CodexSession` (переписан под Codex), счётчик токенов (`ClaudeTokenUsage`
  оригинала читает транскрипты CLI), сверка хода по копиям файлов Claude Code (`UndiffedEdits`), `ForkLineage`,
  а также CHANGELOG, CLAUDE.md, версия и общий сервис статистики `usage-service/` (его списки фич форка сверяет
  тест `codexFork.test.ts`).
- **Правила `.claude/rules` форка стояли на старом снимке ACC `b0e8e19`**, и около 430 строк в 11 правилах были
  потеряны ещё при прошлых переносах: слияние брало «наше» там, где наше было обрезано. Они восстановлены из
  оригинала, а правила прошли переименование тем же преобразованием, что код, поэтому следующие слияния правил
  идут чище.
- После слияния правила, которые описывали механизм Claude Code CLI, переписаны под форк: changed-files,
  session-info, reopen-tabs, fork-tabs, history, models (быстрый режим, список моделей, усилие), indicators
  (ранний сброс, третье кольцо, откуда цифры), accounts (ящики `CODEX_HOME`, автопродолжение, чей вход, Claude
  Design), permissions, stats (токены), scenarios (помощники, аккаунт прогона), turn-lifecycle, hub-files,
  claude-config (экран настроек Codex), claude-home, setting-sources (что у форка вместо экрана), rewind,
  image-preview, editor-context, tab-names, scenario-author, restore-tabs. Сравнения «у оригинала так» оставлены.

## Что под Codex сделано своим

- **Список изменённых файлов хода** (0.13.33, 0.13.40). Результат патча - событие на файл со структурной половиной
  `{filePath, type, movedFrom?}`; удаление и перенос - правки движка отката (`ChangeRevert.Edit.Delete`/`Move`);
  сверка с диском своя (`TurnFiles`: база - чтение файла на `item/started` первого патча, расхождение уходит
  `files_settled`); агенту об откате говорит панель сообщением developer (`PutBack`), потому что Codex не замечает
  изменений снаружи; правки субагентов вкладки входят в список (`CodexSession.spawned`). Откат к сообщению
  (`CodeRewind`) теперь стоит на том же движке. CLAUDE.md, «Список изменённых файлов хода».
- **Быстрый режим** (0.13.43) - уровень обслуживания Codex `priority`. Просьба трёхзначная и живёт с разговором,
  едет с каждым открытием треда и каждым `turn/start`, потому что тир не переживает процесс; правду о тире говорит
  Codex (`thread/settings/updated`), IDE переводит её в `fast_mode_state`. CLAUDE.md, «Режимы, модели, усилие».
- **Автопродолжение** (0.13.42). Codex отдаёт агенту любую остановку как `<turn_aborted>` «The user interrupted the
  previous turn on purpose», поэтому «продолжай» после смены аккаунта и сброса лимита говорит панель. Признак
  «ход прошёл» свой (`refusedTurns`): отказ лимита у Codex - не ошибка хода. Отказы без часов (кредиты рабочего
  пространства, бюджет сессии) не ждутся. Дорога «перезапуск под фоновыми агентами» у вкладок инертна.
- **План, ждущий решения, переезжает на другой аккаунт** с живыми кнопками (`CodexSession.HeldPlan`): ход Codex с
  планом уже кончен, и решить план может любой процесс над тем же тредом.
- **`/status`** (0.13.43): id треда и `codex resume <id>`; у вкладки на добавленном аккаунте на macOS и Linux - с
  ящиком аккаунта перед командой (`ResumeLine`), на Windows - честная подпись. `/status` с телефона отвечает IDE.
  Адреса для других сессий (реестр CLI `sessions/<pid>.json`) у Codex нет вовсе.
- **Токены за день** (0.13.44) - из событий `token_count` файлов тредов; повтор итога в том же файле не считается.
- **Ранний сброс недели** (0.13.43). Фикс оригинала различал целый ответ по списку `limits`, которого у Codex не
  бывает, и у форка не работал: целый ответ теперь помечает перевод (`full_answer`), `ordinaryUsageAllowed` снимает
  отказы, задержка - 35 с вместо 75 (у Codex нет минутного снимка CLI). Лимит трат business-места считается
  лимитом всего аккаунта, и прогон на такое место не уходит.
- **Картинки из истории** (0.13.45) читаются из файла треда (`ThreadPictures`), место своего сообщения в ходе
  разговор помнит (`placeOf`).
- **Форк 0.163 - ссылка на источник** (`history_base` в файле чужого треда, `CodexRollout.fileByKey`), а не копия,
  как в 0.160.
- **Модель хода**: возврат на «Default» едет явной моделью (`modelOnWire`), подпись - модель треда, а не выбор,
  после `model/rerouted` остаток хода подписан моделью перенаправления.
- **Шкала контекста** до первой точной цифры берёт окно каталога для модели и режима Std/Long, как чип CTX.
- **Возврат закрытой вкладки** (0.13.40) несёт две очереди: хаба и то, что `turn/steer` не принял
  (`CodexSession.unsent`).
- Клавиши панели (0.13.30), этап по списку (0.13.39), перетаскивание вкладок между рядами (0.13.37), выключатель
  орфографии (0.13.32), меню чипа открытого файла (0.13.43) - общий код, взяты слиянием.

## Что не перенесено

- Копии файлов Claude Code для сверки хода (`UndiffedEdits`) и досчёт большой правки без диффа: Codex копий не
  ведёт, а каждый `fileChange` несёт патч целиком.
- `ForkLineage`: форк Codex отдаёт унаследованные ходы своим `thread/turns/list`.
- Метка окна в имени модели (`[1m]`, `modelIdentity`) и выученные окна из `result.modelUsage`: у Codex окно - режим
  вкладки и каталог.
- Сигналы фоновых задач CLI (`background_tasks_changed`, `owned_by_subagent`): Codex их не шлёт, у сценария
  работают пары `task_started`/`task_notification`, которые говорит переводчик.
- Архивные разговоры в счёте токенов: `archived_sessions/*.jsonl.zst`, читателя zstd у IDE нет.
- Дедуп копий одного ответа по `message.id` + `requestId`, кэш расхода в своём конфиге и судья чужих цифр
  (`UsageProbes.trust`): у Codex этих задач нет.
- Список целиком - CLAUDE.md, «Что не перенесено и почему».

## Замеры на Codex 0.163 (живые, 2026-10-17)

- Уровень обслуживания: `model/list` даёт моделям `serviceTiers` с `priority` («Fast»), `defaultServiceTier` - null.
  `turn/start` с `serviceTier: priority` - уведомление `thread/settings/updated` с моделью, усилием и тиром;
  следующий ход без поля остаётся на `priority`, уведомления нет. `thread/resume` в новом процессе встаёт на тир
  конфига: тир не переживает процесс. `default` поверх `default` уведомления не даёт. С `service_tier = "default"`
  в конфиге открытие треда на gpt-6-luna, gpt-6-sol и gpt-5.6-sol отвечает `default`: конфиг сильнее каталожного
  `default_service_tier`.
- `fileChange`: на `item/started` файл на диске ещё до патча (добавленного нет, правленый - старый), на
  `item/completed` - после.
- `turn/diff/updated` - сумма патчей, а не диск: после `sed` он всё ещё показывал строку патча. Базой для сверки не
  годится.
- `thread/fork`: файл форка несёт `history_base` (и `forked_from_id`, `forked_from_ordinal_exclusive`) и ни одного
  события `token_count` источника - ссылка, а не копия. Тир ответа форка - `default`.
- `token_count`: 72 из 5073 событий повторяют итог предыдущего в том же файле (обновления только лимитов).
- Архив - `*.jsonl.zst`.
- Писатель у треда один. SIGKILL обёртки `codex` на node оставляет родной `app-server` сиротой, и тот держит тред
  («thread … already has an active writer» у `thread/resume` в другом процессе) до конца хода. Остановка панели
  (закрыть stdin, через 3 с SIGTERM, обёртка его передаёт): на конце ввода старый процесс обрывает ход
  (`turn_aborted` в файле треда) и отпускает тред за 0.8 с, новый процесс поднимается сразу, его ход идёт, файл
  треда цел. Своего хода восстановления после `thread/resume` Codex не запускает.

## Найдено и исправлено (свои баги форка)

- После перезагрузки панели настройки, изменённые с открытия проекта, возвращались старыми: язык, клавиша отправки,
  звуки, передача редактора; смена звука после этого записывала старые обратно. Шире, чем чинил ACC 0.13.32:
  панель получает настройки как есть при каждом подключении.
- Шкала контекста теряла точную цифру при перезагрузке панели, а до первой цифры мерила все модели одним окном (на
  gpt-6.1-sol и в Long - до трёх раз больше правды); смена Std/Long держала старое окно до следующего шага.
- После `model/rerouted` следующий ответ добавлял вторую, ложную строку «переключено Codex, а не вами».
- Возврат на «Default» после выбора модели оставлял разговор на выбранной модели.
- Сообщение, написанное в идущий ход и не принятое `turn/steer`, на конце хода могло уступить сообщению из очереди.
- То же сообщение терялось при смене аккаунта посреди хода.
- План, ждущий решения, снимался при смене аккаунта.
- Форк из истории терял модель, счёт окна и унаследованные вопросы, а поиск «This chat» не находил того, что над
  швом: Codex 0.163 хранит форк ссылкой на источник, и панель по ней не ходила.
- Картинка из сообщения в истории рисовалась двумя чипами: реплей дописывал подпись `[Image #N]`, которую слова уже
  несли.
- Счётчик «tok» у поля считал часть запросов дважды: повтор `token_count` при смене одних лимитов.
- `/status`, набранный на телефоне, уходил модели ходом.

## Найдено в самом ACC

- Разовая отправка открытого файла при выключенной настройке («только с этим сообщением» в меню чипа) молча
  терялась: хаб держит флаг `editor` под настройкой, и агент файла не получал, а карточка писала, что он ушёл. В
  форке разовое включение едет своим флагом `editorOnce` (`EditorContext.goesWith`, `EditorOnceTest`); в оригинале
  не исправлено.

## Проверено

- `./gradlew test` - 1892 теста, 0 падений; панель - `tsc`, `lint`, `vitest` 1890 тестов; `usage-service` - 90 тестов,
  включая сверку списков форка (`codexFork.test.ts`).
- `CodexSessionLiveTest` на `gpt-5.6-luna` (Codex 0.163): разговор с инструментами, разрешение, продолжение в новом
  процессе и чтение из истории; откат с возвратом файла, отказ при непросмотренном сообщении и форк через ход.
- Прогон всех 77 сценариев харнесса на ширине 380, 460, 560 и 1200 px - без единой ошибки страницы.
- Песочница через CDP (WebStorm 2026.2, Codex 0.163):
  - ход «создать патчем, поправить патчем, `sed`» - строка списка `+3`, сверенная с диском; откат удаляет созданный
    файл (ответ IDE за 90 мс), возврат кладёт его таким, каким его оставил ход, вместе с правкой `sed`;
  - после отката следующий ход несёт сообщение developer, и агент без чтения диска отвечает, что файла нет;
  - быстрый режим: переключатель в меню MODEL, ход уходит с `service_tier: priority`, на чипе модели ↯;
  - `/status` - строка `codex resume <id>`;
  - шкала контекста после перезагрузки панели держит точную цифру (Long 828K);
  - экраны Keyboard shortcuts и Spell check; закрытая вкладка возвращается из «Recently closed» на своё место с историей.
- Найдено живьём и починено: откат, нажатый в самом конце хода, ждёт поток событий IDE несколько секунд, и сообщение,
  отправленное в это время, начинало ход без предупреждения агенту. Теперь ход ждёт ответа на нажатие
  (`PutBack.pressed`/`afterPresses`, не дольше 20 с, без блокировки потока), тест `FilesPutBackTest`.
- Не проверено живьём: смена аккаунта посреди хода и автопродолжение после лимита (держат тесты на поддельном
  `codex app-server`), превью картинки над чипом в IDE (держит харнесс), телефон через релей: клиент форка на релей не
  выкатывался.
- Открытый вопрос: в первой песочнице панель шесть раз записала в журнал IDE ошибку React #185 («превышена глубина
  обновлений») при отправке сообщений. Панель при этом работала. Повторить не удалось ни в несжатой панели, ни в
  собранной без сжатия, ни прогоном харнесса; в журналах IDE с оригиналом её нет.
