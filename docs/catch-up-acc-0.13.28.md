# Догоняем оригинал: ACC 0.13.17 - 0.13.28

Перенос 2026-10-09. Предыдущий шаг - `docs/catch-up-acc-0.13.16.md`.

## Как переносилось

- Точка: форк уже содержал ACC до 0.13.16 (перенос 0.2.0), плюс свои порты 0.13.19 (подвал меню, 0.2.3) и
  0.13.20 (жизнь браузера панели, 0.2.4). Диапазон оригинала `04bc17a..5280788`: 31 коммит, ~23 тыс. строк.
- Трёхстороннее слияние `git merge-file` всего диапазона с переименованием под форк (`amazingclaudecode` ->
  `amazingcodex`, `claude/` -> `codex/`, `Claude*` -> `Codex*`): 109 файлов взято, 38 слито чисто, 19 с
  конфликтами разобрано руками. Для `SideMenu.tsx` основание слияния - коммит 0.13.19, уже перенесённый.
- Не сливались, а переносились руками: `CodexSession`, `CodexHistory` (переписаны под Codex), а также всё,
  что держалось на транскрипте и служебных запросах Claude CLI (`TranscriptRewinds`, `ForkLineage`,
  `AwaitedControls`, флаг `--resume-session-at`, переменная чекпоинтов) - они удалены и заменены своим.

## Что под Codex сделано своим

- Откат - `thread/revert`, код - откатом применённых патчей (`CodeRewind`), сегменты треда после ревёрта -
  `CodexRollout`. Точка форка - ход (`lastTurnId`). Подробно - CLAUDE.md, «Откат к сообщению и точные форки».
- Фоновые помощники карточки сценария - субагенты Codex (`collabAgentToolCall`), которые Codex не возвращает
  родителю сам; движок просит карточку собрать их ответы. CLAUDE.md, «Сценарии под Codex».
- Отказ по лимиту говорится ответом `<synthetic>` с `rate_limit`, как у Claude Code, - на нём стоит переезд
  прогона на другой аккаунт (`LimitRelief`).
- Тексты отката во всех 10 языках - про Codex, плюс состояние диалога `changed` (файлы изменены после правок).
- Съёмка картинок для стора (`scripts/listing/`, скилл `/listing-shots`): порты форка, полка `.codex/scenarios`,
  модели Codex, режимы Codex («Plan» ради вопроса с вариантами), прошлый дубль архивируется через `codex
  app-server`.

## Что не перенесено

- Моды Claude Code (0.13.27) - у Codex их нет; части панели взяты и молчат.
- Настройка «Rewind code (checkpoints)» - у Codex её нет, возврат кода доступен всегда.

## Замеры на Codex 0.160 (живые)

- `thread/revert`: модель забывает отрезанное; новый файл-сегмент с `history_base`, смещения на границах
  строк, цепочки сегментов, `thread/list` перечисляет каждый файл отдельно с тем же id; `thread/resume`
  читает тред как надо.
- `thread/fork` с `lastTurnId`: форк несёт ровно ходы до точки, id ходов сохраняются, файл пишется сразу.
- Форма `fileChange`: `add`/`delete` - текст файла целиком, `update` - unified diff, у переноса - `move_path`
  и хвост «Moved to: …» после диффа.
- Субагент (`spawnAgent`) живёт своим тредом; ход родителя кончается сразу, конец субагента родителю не
  сообщается и новый ход у родителя не начинается.
- `request_user_input` открыт только в режиме плана (`default_mode_request_user_input` выключен).

## Найдено при проверке (в оригинале не исправлено)

- Номера запросов разрешений (`codex-<эпоха>-<id>`) совпадали у разных разговоров - эпоха стала общей на IDE.
- Пара с телефоном на macOS: секреты всех устройств лежали в одной записи keychain и затирали друг друга;
  запись `RemoteState` не сохранялась первые пять минут после старта IDE (порог платформы для неперемещаемых
  настроек); секрет без записи пускал телефон, которому не доходил ни один ответ (история, прошлый прогон,
  поиск). Подробно - `.claude/rules/remote-access.md`, «Пара - это две записи». Ровно то же сломано в ACC.
