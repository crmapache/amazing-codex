## ID разговора: `/status` и меню правой кнопки

Пришло отзывом (0.13.41, IntelliJ IDEA на маке): «хочу, чтобы агент передал что-то в другую сессию, для этого
нужен её id - дайте его прочитать или скопировать». Панель id разговора не показывала нигде.

**Адреса для других сессий в карточке нет, и у Codex его взять неоткуда.** В оригинале первая версия карточки
показывала имя, по которому разговору пишут другие сессии Claude Code (CLI ведёт реестр запущенных процессов в
`sessions/<pid>.json`, у агента есть инструменты «список сессий» и «отправить сообщение»). Живьём агент принял
вставленное имя за непонятный идентификатор и пошёл искать его по репозиторию, и Макс сказал «убери вообще». У
Codex нет ни такого реестра, ни инструментов переписки между тредами, так что в форке карточка с самого начала -
id треда и команда для терминала.

- **`/status` - команда панели** (`panelCommands` в `catalog.ts`, `runLocal` в `App.tsx`). У `app-server` слэш-команд
  нет вовсе. Панель шлёт `sessionInfo`, окно отвечает (`CodexPanel.sendSessionInfo` → `CodexSessionHub.sessionInfo`),
  в ленте встаёт строка `SessionInfoRow`: id треда Codex и команда для терминала (см. «Строка для терминала у Codex»). Заголовок сверху и поля столбиком: подпись с
  пояснением, под ней значение плашкой, которая копируется целиком по клику (`CopyButton` с `children`). Первая версия была таблицей с колонкой под одно слово «SESSION» и копированием квадратиком сбоку -
  Макс: «смотрится стрёмно, под тайтл не надо целый столбец». Столбиком карточка одинакова на любой ширине.
  Строка локальная: в журнал не пишется, другие клиенты её не видят, после перезагрузки панели её нет - это ответ
  на вопрос в моменте, как вывод `/status` в терминале.
- **Id берётся у IDE** (`conversationIdOf`), а без него - из состояния вкладки (`case 'sessionInfo'`): сброс
  состояния панели свою отметку теряет, IDE - нет.
- **Меню правой кнопки собирает браузер, а не страница** (`PanelContextMenu`, ставится в `WebviewHost`). Раньше
  там стояли браузерные Back, Forward, Print, View Page Source. Убираются они поимённо (`BROWSER_ONLY`), а не
  оставляется разрешённое: правка над полем, Copy над выделением, подсказки орфографии и всё, что браузер
  добавит завтра, остаются, пока кто-нибудь не решит иначе. Разделители, оставшиеся с краю или подряд,
  снимаются (`dropped`, с тестом). Пустое меню CEF не показывает вовсе.
- **Пункт «Copy Session ID» знает вкладку заранее.** Меню строится на потоке браузера, и спросить страницу в этот
  момент нельзя: ответ не успеет. Поэтому страница сама сообщает окну открытый разговор и слова для пункта при
  каждой смене вкладки или её разговора (сообщение `sessionMenu`, `WebviewHost.sessionMenu`). Слова едут со
  страницы, потому что словаря панели у IDE нет. У вкладки без разговора (новая, статистика, сценарии) пункта
  нет.
- **Эффект, который шлёт `sessionMenu`, стоит выше раннего выхода `App`** (экран входа). Поставленный ниже, он
  менял порядок хуков между отрисовками, и харнесс падал белым экраном.
- **Режим браузера в отдельном процессе тоже это умеет.** В WebStorm 2026.2 браузер панели живёт в `cef_server`
  (удалённый JCEF), и меню там идёт через `RemoteMenuModel` - список, на котором работают все вызовы,
  которыми пользуется `PanelContextMenu` (проверено по классам платформы).
- `sessionMenu` и `sessionInfo` телефону запрещены (`RemoteCommands.DENIED`): меню есть только у окна IDE, а
  строка - ответ своей ленте. Счёт: фича `session_info` и на `/status`, и на копирование из меню
  (`onSessionIdCopied`, пункт меню строит окно, сообщения нет), и на `/status` с телефона (`statusAsked`).

### Строка для терминала у Codex

- **Команда - `codex resume <id>`, и пишет её функция, а не разметка** (`resumeCommand`, `resumeNote` в
  `feed/sessionInfo.ts`, с тестом): строка в `Rows.tsx` - код оригинала, где стоит `claude --resume`, и разница
  форка там - один вызов, чтобы следующее слияние строки было слиянием строки.
- **Вкладка на добавленном аккаунте - это свой `CODEX_HOME`** (`~/.amazing-codex/accounts/<id>/`). Голый
  `codex resume <id>` в своём терминале тред найдёт (разговоры общие), но продолжит его на входе по умолчанию, а не
  на аккаунте вкладки: молча, и ходы уйдут другой подписке. Поэтому строку решает IDE (`ResumeLine`, с тестом):
  - **macOS и Linux - ящик перед командой**: `CODEX_HOME=<ящик> CODEX_SQLITE_HOME=<обычный дом>`, плюс пустые
    `OPENAI_API_KEY=`/`CODEX_API_KEY=`/`CODEX_ACCESS_TOKEN=` для тех из них, что есть в окружении оболочки IDE (они
    перебили бы ящик, см. `AccountStore.OUTRANKING_VARIABLES`). Форма `VAR=value команда` одна для sh, bash, zsh и
    fish с 3.1, ставит переменные только этой команде, а оболочка, которая её не понимает (csh, старый fish,
    PowerShell), ругается на всю строку вслух и Codex не запускает - на вход по умолчанию молча не уедет. Путь в
    кавычках, только если без них оболочка что-то в нём прочитает (`ResumeLine.word`). Ящик и дом -
    `CodexAccounts.terminalHomes` с теми же отказами, что у запуска, но без синхронизации ящика.
  - **Windows - строка голая и честная подпись** («продолжит на входе Codex по умолчанию, а не на <аккаунт>»,
    `onDefault`). Одной формы там нет: `$env:` у PowerShell и `set` у cmd остаются в терминале до конца (следующий
    голый `codex` там же молча уйдёт на аккаунт), и каждая - ошибка в другой оболочке; угадывать, куда вставят
    строку, IDE не берётся. Так же для ящика, который не разрешается (у вкладки на нём не запустится и процесс).
  - Подпись называет аккаунт (`terminalNoteOn`/`terminalNoteDefault`, имя - псевдоним, иначе адрес; без того и
    другого - `unnamedAccount`). На входе по умолчанию подпись прежняя.
- **`/status`, набранный на телефоне, отвечает IDE, а не модель** (`SessionCommands.statusAsked`,
  `CodexCommands.isStatus`, тест `SessionInfoTest`). Телефон шлёт его обычным сообщением (`prompt` или
  `queuePrompt`), и без этого он уходил модели ходом - потраченный ход на «у меня нет команды /status» (CLI
  оригинала такую команду в потоке отклонял сам). Теперь у двери сообщений IDE отвечает той же строкой только
  спросившему (`emitTo`), подтверждает сообщение как обычно (`promptReceived`), ни эха, ни хода. Телефону строка
  с ящиком не отдаётся (пути машины наружу не уходят), поэтому у вкладки на добавленном аккаунте там всегда
  `onDefault`. Телефон рисует её общей `SessionInfoRow` (`case 'sessionInfo'` в `mobile/feed.ts`), держит `/status`
  в подсказке `/` (`STATUS_COMMAND` в `mobile/facts.ts`) и не называет по нему новую вкладку (`isStatusCommand`).
- Проверить без IDE: харнесс, любой сценарий с полем - набрать `/status` и Enter, плеер отвечает выдуманным
  id, клик по плашке меняет значок на галочку. Строку для аккаунта плеер не играет: её решает IDE (`ResumeLineTest`,
  `sessionInfo.test.ts`). Меню правой кнопки
  в харнессе не видно, это меню браузера IDE: живьём - песочница, правый клик по ленте (пусто без выделения,
  кроме «Copy Session ID»), по выделению (Copy и пункт), по полю ввода (правка, орфография и пункт).
